# hynix-interview

해법을 정하기 전에, 업무 담당자에게 무엇을 물어야 하는지 정리한다.

## 절차

1. README.md를 읽고 요구사항을 세 가지로 나눈다: **명시됨 / 모호함 / 언급 없음**.
2. 데이터 파일이 있으면 파일마다 프로파일을 출력한다. 큰 파일은 `head`, `wc -l`, 짧은 스크립트로만 본다.
   - 행 수, 열 이름과 형식, 결측 수, 완전 중복·키 중복 수
   - 시간 열: 형식과 시간대 혼재(`Z`, `+09:00`, 표기 없음), 범위
   - 범주 열: 고유값과 빈도 상위 10개, 철자·대소문자 변형
   - 수치 열: 최솟값, 최댓값, 이상치 후보
3. 프로파일에서 발견한 이상한 점마다 "이건 업무상 어떻게 처리하나요?" 질문을 만든다.
4. 아래 범주로 질문을 8~12개 만든다. 해법을 묻지 말고 **업무 사실**을 묻는다.
   - 사용자와 사용 상황: 누가, 언제, 결과로 무슨 결정을 하나
   - 현재 방식과 불편: 지금은 어떻게 하고, 무엇이 틀리거나 느린가
   - 판정 기준과 수치: 임계값, 경계값 포함 여부, 우선순위
   - 데이터 규칙: 시간대, 중복·재처리, 제외 대상, 결측 처리
   - 예외: 야간·주말, 특정 설비·제품, 수동 개입
   - 완료 기준: 무엇을 보면 "됐다"고 판단하나
   - 범위 밖: 이번에 하지 않아도 되는 것
5. INTERVIEW.md가 없으면 만들고, 있으면 아래 두 절을 덧붙인다(기존 내용은 지우지 않는다).
   - `## 데이터 프로파일`: 2번 결과를 짧은 표로
   - `## 질문 목록`: 우선순위 순, 각 질문 옆에 "왜 묻는지" 한 줄
6. 질문 목록 상위 5개를 화면에 보여 주고 멈춘다.

## 하지 말 것
- 질문의 답을 추측해서 PLAN.md나 코드에 반영하지 않는다.
- 데이터 파일을 수정하지 않는다.
