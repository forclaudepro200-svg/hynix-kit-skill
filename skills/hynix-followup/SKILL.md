# hynix-followup

후속 서술형(6문항, 문항당 5분, AI 금지)은 제출물과 작업 기록을 바탕으로 출제된다. 제출 전에 내가 설명해야 할 지점을 미리 정리한다.

## 절차

1. 아래를 읽는다(큰 파일은 핵심 함수만).
   - PLAN.md, DECISIONS.md, HANDOFF.md, INTERVIEW.md
   - `git log --oneline`
   - 핵심 판정·계산 로직이 있는 파일 2~3개
2. 예상 질문 6개를 만든다. 유형을 섞는다.
   - **왜** 이렇게 구현했나(대안 대비) — 2개
   - 이 부분이 **실패하면** 어떻게 되고 어떻게 대응하나 — 2개
   - 이 **데이터 규칙·경계값**은 어떻게 처리했고 근거는 무엇인가 — 1개
   - 시간이 더 있었다면 무엇을 **검증·개선**하겠나 — 1개
   각 질문은 실제 파일·함수·결정 번호(D1…)를 짚어야 한다. 일반론 질문은 만들지 않는다.
3. 질문마다 답변 뼈대를 쓴다. 문장으로 다 쓰지 말고 키워드로 쓴다(사용자가 직접 말로 풀어 쓸 수 있게).
   ```
   Q1. <질문>
   - 위치: <파일:함수 / 결정 D번호>
   - 한 일: <무엇을 어떻게>
   - 이유: <근거, 업무 담당자 발언, 대안을 버린 이유>
   - 약점: <구체적 입력이나 상황에서 깨지는 점>
   - 파급: <틀리면 누가 무엇을 잘못 판단하나>
   - 다음: <검증하거나 개선할 것>
   ```
4. 맨 끝에 `## 외울 숫자`를 만든다: 입력·제외·처리 행 수, 테스트 수와 통과 수, 임계값, 성공 기준 개수 등 답변에 쓸 실제 수치.
5. FOLLOWUP_PREP.md에 저장하고 질문 6개만 화면에 보여 준 뒤 멈춘다.

## 주의
- 문서와 코드가 다르면 **코드 기준**으로 답변 뼈대를 쓰고, 불일치를 질문 목록 위에 따로 표시한다.
- 실제 하지 않은 검증을 한 것처럼 쓰지 않는다.
