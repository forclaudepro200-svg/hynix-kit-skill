# hynix-deliverables

README가 요구하는 제출물을 빠짐없이 목록으로 만들고, 정해진 이름·경로대로 자리를 잡아 둔다.

## 절차

1. README.md에서 제출·결과물·필수·산출물·형식·실행 방법에 해당하는 문장을 모두 찾는다. 과제 안내 파일이 따로 있으면(예: `TASK.md`, `docs/`) 그것도 본다.
2. 제출물을 세 종류로 나눈다. 항목마다 **README 원문 근거 한 구절**을 붙인다.
   - **코드**: 실행 진입점, 실행 명령, 언어 지정
   - **결과 파일**: 경로, 형식(JSON·CSV 등), 필수 필드·스키마, 값의 허용 범위
   - **문서**: 파일명(지정된 경우), 꼭 담아야 할 내용
3. PLAN.md 맨 위(제목 바로 아래)에 `## 0. 제출물 체크리스트` 절을 넣는다. 이미 있으면 갱신한다.
   ```
   | # | 종류 | 경로 | 요구사항 (형식·필드) | README 근거 | 상태 |
   |---|---|---|---|---|---|
   | F1 | 결과 | output/report.json | overall[], night_shift[] … | "결과는 …" | 미생성 |
   ```
   README에 없는 것은 넣지 않는다. 애매하면 `확인 필요`로 표시하고 업무 담당자에게 물을 질문을 한 줄 적는다.
4. 파일과 폴더를 만든다. **이미 있는 파일은 덮어쓰지 않는다.**
   - **폴더**: 결과 파일 경로의 폴더를 만든다(예: `output/`).
   - **문서**: README가 문서 파일명을 지정했으면 그 이름으로 만든다. 내용은 README가 요구한 항목을 제목(`##`)으로만 둔다. 키트 문서(PLAN·DECISIONS·HANDOFF)와 겹치면 지정 파일에 "상세는 PLAN.md, DECISIONS.md, HANDOFF.md 참고"를 적고 마무리 때 요약을 옮길 수 있게 한다.
   - **결과 파일과 코드는 만들지 않는다.** 빈 결과 파일이나 가짜 값은 "제출 완료"처럼 보이는 거짓 성공이 된다. 결과 파일은 코드를 실행해서만 생성한다(`hynix-build` C0부터).
5. 결과 파일의 스키마가 README에 있으면 `test/` 또는 테스트 폴더에 스키마 확인 테스트를 **기준 없이 추가하지 말고**, PLAN.md 성공 기준 후보로만 제안한다(예: `C? report.json이 README 스키마를 만족`).
6. 커밋한다: `setup: README 제출물 체크리스트와 경로`. 실패하면 오류와 직접 실행할 명령을 보고한다.
7. 보고하고 멈춘다.
   - 제출물 체크리스트 표
   - 만든 폴더·파일 / 건너뛴 파일
   - `확인 필요` 항목과 질문
   - 제안한 성공 기준 후보

## 하지 말 것
- README에 없는 제출물을 지어내지 않는다.
- 결과 파일, 코드, 테스트를 만들지 않는다.
- 문서 본문을 추측으로 채우지 않는다.
